# 用户旅程技术债务清单

## 使用方式

本清单只记录会影响真实用户旅程的未完成债务，不按文件夹或代码行数安排清理。每次开发触及某条旅程时，选择能够独立验证、独立回滚的最小一项一起收口；没有行为证据时不删除兼容路径。

| 优先级 | 用户旅程 | 债务与当前证据 | 必须保留 | 验收 | 回滚点 |
| --- | --- | --- | --- | --- | --- |
| P0 | 登录失效 → 恢复阅读或互动 | managed read、启动恢复、账号刷新和已触及的写路径已做到单站凭据失败隔离，并保证自动清理失败不覆盖原始登录失效结果；剩余债务是各站写操作仍由 controller / action client 分别组装来源细节 | 已有登录态、Cloudflare 验证、普通请求优先与 WebView fallback、代理 fail-closed | 三个登录来源分别覆盖有效、失效、仅验证、存储异常和普通网络错误；失效后能从 App 内入口恢复，其他来源不受影响 | 保持 managed read interface 稳定；每次只收口一个写入路径，失败时恢复该路径原调用，不改现有主凭据安全存储键或 Cookie 格式；撤销标记只能按既定的 App 内重新登录流程解除 |
| P0 | 写操作 → 成功或状态回滚 | 来源静态 capability、原站结构化事实和 UI 操作状态尚未形成完整的单一判定链，容易出现“来源支持但当前对象不允许”的入口 | 原站明确权限、确认步骤、防重复提交、失败或结果无法确认时保留草稿并恢复计数 | 未登录或缺少 credential / id / link 等必需字段时不发送；成功不重复计数；失败或结果无法确认时草稿可编辑、乐观状态回滚 | 以单项 action 为提交和回滚单位；保留原请求格式，不改变现有主凭据安全存储键、Cookie 格式或备份结构 |

## 清理约束

- `src/sources/sourceGateway.ts` 是统一读取 seam，新读取调用方不得绕过它；写操作目前按 capability 由 `src/app/useTopicActionsController.ts` 调用各站 action client，并在触及具体路径时逐项收口。
- `App.tsx`、`src/theme.ts`、`src/screens/TopicScreen.tsx` 继续作为入口或兼容 facade，不因“文件薄”而删除。
- `android/` 是生成目录，不把生成结果当长期配置，也不把删除生成目录算作产品债务完成。
- 每项债务完成时，在对应测试和真实旅程验收通过后从本清单删除；未完成部分应缩小描述，不能改名后继续悬空。
