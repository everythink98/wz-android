# 正文解析与 Worker：减少重复工作，保留完整结算

本文解释 2026-10-18 至 2026-10-19 正文性能实验中的有效发现、失败假设和继续条件，供以后选择最小改动时使用。它不是运行手册，也不替代产品地图或回归语料库。

重新筛选局部优化时的已提交基线为 `fa491fa1`。此后的四项局部改动与本手册一同纳入提交，正式产包状态以发布记录为准，局部机制通过不能写成已发布的体验收益。正文与整页 Worker 曾进入实验普通包，随后随整体方案回退；本文中的 Worker 门槛、队列和结果均属于历史实验，不是现役配置。

历史原件删除不影响本文的机制与有限结论，也不影响阅读；原件和旧实验入口不作为当前复现前提。下文列出的现有测试是继续建立反例的入口，不表示仍保留已撤回的 Worker 测试。

## 先区分哪一段工作占用了线程

历史 NodeSeek 链路包含几个独立阶段：

1. 取得 HTTP 响应并读取 HTML。
2. 解析整页 DOM、来源身份、权限提示、主题与回复元数据。
3. 读取正文依赖的投票信息。
4. 清洗正文、归一化媒体、规划物理行，再提交给界面。

正文准备慢，不等于页面 DOM 解析慢；两者又都不等于图片解码或首次绘制慢。只迁移第四段，第二段仍可能连续占用 RN JS 线程。

同样，图片多不代表所有逐图分支都会执行。需要先保留实际输入、调用点和完整输出，确认优化命中了用户正在看的内容。

## 已验证可拆的重复工作

### 只需要属性名时，不解码所有属性值

原问题与原因：正文清洗后的编译器自有属性删除，只需要匹配属性名。原实现读取 `node.attributes`，parser 的 getter 会重新解码全部值并分配对象。

已做、已验：一份公开正文有 2826 个元素。局部候选改读 `rawAttributes` 的键后，目标 getter 调用从 2826 次降到零；其他确实需要属性值的消费者仍读取 2826 次。完整输出一致，保留 354 行、1413 个媒体项及顺序。

处理与踩坑：2026-10-19 已重新实施这一行候选，保留属性删除、安全清洗和需要解码值的消费者，不扩大成跨阶段缓存。混合大小写、实体、伪造编译器属性和表格样本也保持原输出；不能为了省 getter 跳过安全清洗。

未验证：没有可比的整页耗时或帧率收益。当前入口为 `src/domain/forum/topicContentSplit.test.ts`，可在真实清洗后节点上统计属性 getter，核对伪造键删除、实体值及完整输出；共享守恒归 `tests/integration/forum-presentation-contracts.test.ts`。

### 同次解析复用未变动的节点列表

原问题与原因：NodeSeek 页面解析已经建立全量 element index，随后权限提示扫描又对同一 root 枚举一次全部节点。两次消费之间没有修改 DOM，重复枚举可以消除。

另一处无用工作发生在正文原文提取：精确原始范围供表单投票归一化使用，无表单时最终仍消费既有 DOM 的 `innerHTML`，却提前复制整段正文并查找边界。

已做、已验：行为断言分别观察到全量枚举两次而不是一次，以及无表单原文切片一次而不是零次。复用同次节点列表，并把原文范围提取限制在含表单分支后，这两项分别降为一次和零次，原内容语义断言保留。

处理与踩坑：2026-10-19 已重新实施这两个局部候选，不需要 Worker、跨请求缓存或来源协议变化。不能顺带恢复历史异步整页解析的日期参数与 reader 接线。

风险集中在权限提示、正文容器优先级和投票表单上下文；元素自身不应被误当成自己的祖先，真实表单仍须保留精确原文。

未验证：没有同包可比的整页提速结论。继续从 `src/sources/nodeseek/topicParser.test.ts` 构造普通、受限、空内容及有/无表单输入，统计同 root 的枚举和切片；由 `src/sources/nodeseek/reader.test.ts` 与 `tests/integration/source-read-contracts/nodeseek.test.ts` 核对完整读取结果。

## 有效的小优化，也可能没有命中真实样本

### 直接创建图片标签的文本节点

原问题与已做：共享媒体归一化把已经转义的图片替代标签传给 `set_content(string)`，导致行内图片标签再次经过 HTML parser。试过直接传入 `TextNode`，保留文字、实体转义和 parent 关系并跳过这次解析。

已验：合成的 1413 张行内图片可以复现逐图重解析，完整 prepare 输出比较支持局部替换。真实公开 DOM 在图片之间包含换行节点，全部走 standalone 图片路径，没有触发这段替代标签处理。

踩坑与处理：合成输入命中不等于现场命中。这项仍未恢复，不能作为那份重图帖卡顿的根因修复。历史普通包准备耗时的单次前后样本没有显示明确提速，预热条件也不一致。

未验证与重开条件：先取得当前现场命中行内路径的证据。可从 `src/domain/forum/forumContentMedia.test.ts` 构造 alt/title 含实体与类似标签的纯文字，观察零字符串重解析、文字和 parent 关系，再比较完整 prepare 输出；不能只保留计数断言。

### 只有 DOM 未变时才复用引用文本索引

原问题与已做：NodeSeek 引用识别先建立段落文字索引，处理段首引用后又为链接建立全文索引。试过在 DOM 未变时复用第一份索引；发生替换时仍重新建立。

已验：合成长文的前缀数组分配从 721112 bytes 降到 360556 bytes，完整输出相同；未改变 DOM 的用例索引两次降为一次，段首替换后仍为两次。这是特定含链接分支的分配减少，不是整体内存下降。

踩坑与处理：真实公开重图正文没有链接，该分支本来就提前返回。这项仍未恢复，不能改用合成长文后沿用原现场结论。

未验证与重开条件：先证明当前目标正文含相关链接且索引占用值得处理。可在 `src/domain/forum/topicContentHtml.test.ts` 分别构造普通链接、行内引用、段首引用替换及后续楼层链接，核对一次/两次索引预算与相同输出；实际帧时须另测。

### URL 在两个阶段解析，不一定是重复职责

已做、已验：对同一真实输入统计 URL 构造调用，sanitizer 解析地址以规范化并校验协议，media 再读取 host、path 和 protocol 识别媒体。没有发现 preview 或 selection 又进行第三遍解析。

原因与踩坑：相同 URL 的两次解析分别承担安全与展示职责。跨阶段共享结果会增加上下文、属性变更失效规则及独立 compile、fallback、分享接线，不能直接删除安全边界或共享可变 URL 对象。

处理与未验证：没有继续做产品候选，没有跨阶段缓存的功能或耗时证据。仅在新 profile 证明值得增加接口时重开；先对清洗、媒体和预览各阶段分别计数，再以当前 `src/domain/forum/forumContentMedia.test.ts` 与 presentation contract 验证相同地址、独立调用及属性变化后的正确性。

## Worker 解决阻塞位置，不保证更快完成

已做：先把正文清洗和行规划迁到独立 Hermes runtime，后又尝试把整页纯解析迁走。Response、诊断 WeakMap、投票网络读取和最终提交仍留在 reader 一侧。原因是只迁移正文准备，整页 DOM 解析仍可能阻塞 RN。

| 历史准入对象 | 实验门槛 | 单位与限制 |
| --- | --- | --- |
| 独立正文准备 | `128 * 1024` | 输入字符串的 UTF-16 code unit 数，不是 HTTP bytes 或图片数 |
| 整页纯解析 | `160 * 1024` | 整页 HTML 的 UTF-16 code unit 数，正文门槛独立保留 |

这些数值只覆盖已校准的大输入附近，不代表找到最优分界。小页面可能被初始化、复制和往返成本拖慢；没有数据就不应把所有页面统一迁走。

已验的两组代价来自不同实验，不能互相相减或拼成一条优化曲线：

| 历史实验与对照条件 | 结果及代价 | 不能外推的范围 |
| --- | --- | --- |
| 正文隔离实验：181475 bytes 的保存主楼输入，直接比较 RN 正文准备与 Worker 正文准备，初始化另列 | 首份正文往返约 `323→442 ms`，RN timer 最大间隔约 `339→35 ms`；暖样本约 `308→417 ms` | 没有整页 DOM、真实 HTTP 或完整产品 UI；前后边界 timer 样本另有包络，不能把 timer 间隔当成纯函数耗时 |
| 整页隔离校准：另一份公开主楼加合成 wrapper；两侧均调用真实 reader、保留大正文 opening Worker，候选只额外迁移整页解析；各两轮且交换顺序 | 巨型页整链约 `536→559–561 ms`，RN timer 最大间隔约 `121→34 ms`，额外总耗时约 23–24 ms | 不是上一行输入；顺序任务不验证生产 slot、取消或超时，小、中页无稳定收益，512 图页两轮改善不一致 |

踩坑与未验证：减少 RN 连续阻塞可能增加总耗时。timer 继续触发不代表屏幕及时呈现、连续手势跟手或 deadline miss 减少。两组实验都不能证明普通帖子打开更快，Worker 未随当前局部候选恢复。

## 取消调用者，不等于底层计算停止

原问题与原因：A 主题被取消后，Native 编译还持有共享 slot；B 主题到达时发现 busy，返回「Worker 不可用」，reader 随即在 RN 同步重算。真实 reader 的反例观察到一次不应发生的同步编译。

这会在最需要让出 RN 线程时把工作搬回来。busy 表示前一任务尚未结算，不能等同于环境不支持或编译失败。

已做：后续实验采用以下边界：

1. 等待者留在 RN 可取消等待，不提前向 SDK 派发下一项任务。
2. 取消只结束本调用者的等待；底层任务仍须观察到真实 Promise 结算。
3. 只有底层结算才释放 slot；唤醒后再次检查 busy 和取消状态，不假定 FIFO。
4. 等待者离开时移除等待集合项和 abort 监听，避免取消后仍被保留。
5. 30 秒预算覆盖等待、初始化和编译。底层永久不结算时，后续调用按期限失败，不能伪造空结果或提前释放占位。

小正文、不支持环境及已结算失败的既有同步回退，与 busy、调用者取消、计算超时是不同分支。取消后不得重算，超时也不得绕回同步编译来制造成功。

两类 Worker 共用一个 runtime 和 slot。整页结果返回后释放占位，再做投票 I/O，之后才申请正文准备；不能跨网络等待持有计算 slot。

已验、踩坑：最初只看到外层取消和 B 返回 Promise，无法排除 SDK 已预先排队。后续透明 observer 保留真实 SDK 参数和原 Promise，才补证 A 底层 settlement 早于 B page enqueue，page settlement 又早于 B opening enqueue，最终 API 与 SDK pending 均归零。

未验证：补验绑定单一 runtime，B 使用公开正文加合成 wrapper 和受控 Fetcher，核对了完整结果、投票请求、提交与诊断；没有覆盖真实网络下的完整 UI 快速换帖，也没有证明物理抢占取消或永久不结算的真实 Native 故障。

重建方法：将透明 SDK observer 接在新候选的唯一 owner，保留原参数和 Promise；先要求 A 底层 pending，再取消调用者并通过真实 reader 发起 B，验证派发顺序与最终 pending 归零。SDK settlement 包含回传，不等同于精确 Native CPU 结束时刻，不应重用旧实验入口或固定 PID。

## 计算错误不能被网络恢复重新播放

原问题与踩坑原因：纯解析进入异步边界后，计算超时可能与 HTTP 超时共用错误类型。若外层 read gateway 把它当作网络故障，就可能打开验证、恢复请求，把已取得的页面重新抓取或重复编译。

已做、已验：历史真实 reader 与 gateway 受控反例分别覆盖取消不重算、计算超时不恢复网络或重放，并核对迟到结果不再触发投票或 apply。不能只检查外层 Promise 是否 rejected。

纯函数等值也不能只比较 JSON 字符串：历史比较保留 own keys、`undefined`、数组形状、请求、Response 提交和诊断顺序。缺失来源日期时跨 `await` 的取时差异须单列，固定时钟的测试不能证明现实日期逐值相同。

未验证与复现入口：当前没有 Worker 接线，不能声称这些反例仍在运行。重新引入时，在现有 `src/sources/nodeseek/reader.test.ts` 和 `src/sources/readGatewayContract.test.ts` 接入真实候选，仅控制 SDK 与 Fetcher，分别制造 unavailable、busy、取消、计算超时和迟到成功；检查请求次数、同步编译次数、投票与最终提交，另以匹配普通包验证实际界面交错。

## 什么时候值得继续

本轮重新实施并纳入提交的局部改动，消除了有同输入反例的重复枚举、无用切片和属性解码；下一次应复核当前实现而不是再次恢复。编辑器缓存与回调稳定性的经验由同目录其他专题展开，不能和正文线程迁移合并算成一次收益。

Worker 暂不恢复。重新启动前，先用一个当前匹配包确认：剩余长阻塞仍发生在纯解析或正文准备，且局部去重后仍足以影响用户交互。若主要成本已转到 Native mount、draw 或媒体解码，应沿对应线程继续定位。

随后只重建一条最小迁移路径：固定真实输入和完整输出，分别计算冷初始化、暖调用、跨 runtime 往返与整链耗时，并保留小页的负收益对照。重新选择门槛，不能沿用历史数字当作通过条件。

生命周期验收须同时观察调用者和底层任务：A 取消后 B 的排队、page/opening 共享 slot、等待超时、迟到结算、取消后的同步调用与跨网络重放。旧的隔离顺序校准或普通 UI Back 各自只能覆盖其中一部分。

历史普通包确有一次页面解析后 Android Back 的功能取消记录：同次 trace 后续没有 apply 或正文 ready，返回首页成功；后续刷新又分别完成两类 Worker。这两段不能拼成一次取消后立即换帖的并发证明，也不能由无标记推断底层 CPU 已停止。

只有同时取得匹配源码的功能非回退、真实底层结算和可比交互改善，才值得再次采用线程迁移。timer、工作次数、CPU Running、帧时和触摸感受分别报告；一次 PSS 升降或零崩溃不能替代长期内存和完整媒体容量验收。

当前入口和现行验证归属继续以 [产品地图](../product-map.md)、[测试标准](../testing-standard.md) 为准；构建、覆盖安装和设备身份检查沿用[维护手册](../operator-runbook.md)，本文不复制执行命令。
