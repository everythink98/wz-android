# 性能与回归踩坑手册

本文汇总截至 2026-10-19 的性能探索与相邻回归经验，回答做过什么、验证了什么、踩了什么坑，以及为什么会这样。关键条件、结果和结论直接写入正文，删除本机快照、日志或实验脚本后仍可独立使用。

本手册保存历史实验与判断依据。当前产品行为以[产品地图](../product-map.md)为准，事故状态以[回归语料库](../regression-corpus.md)为准，待处理项以[技术债务清单](../code-cleanup-map.md)为准。实验通过不等于当前代码包含该方案，也不授权恢复已撤回的改动。

## 实验结论如何使用

| 结论类型 | 能支持什么 | 不能据此做什么 |
| --- | --- | --- |
| 已验证的局部机制 | 同输入修前断言失败，修后重复工作减少，且相关内容与行为保持 | 宣称真机更跟手、FPS 提升或全部卡顿消失 |
| 有限设备观察 | 指定包、设备、路径和窗口内的实际现象 | 合并不同包、内容和工具的结果，充当一次完整验收 |
| 当轮否决或未恢复 | 已知收益不足、代价或证据缺口，足以停止原路线 | 没有新证据时原样重做，也不能解释为永远不可能有用 |
| 未验证 | 尚缺决定性证据，或者原采集不足以回答问题 | 把假设记为根因，把未复现写成已修复 |

各专题区分源码与断言已确认的机制，以及尚未与用户现场完全对应的现象。后者保留为未验证，不补造确定解释。

## 已经做过的取舍

- 只在实际命中路径消除重复工作。合成输入上的收益不能自动套到图片全部独立成行、没有链接的真实重图帖。
- 对不变文档和编辑状态复用最近结果，保留每次权限、身份、投票和发送校验，不能缓存整个业务快照。
- Worker 降低过 RN 定时器阻塞，但增加过总处理时间，还需要取消与真实任务结算约束。当轮已撤回，不默认恢复。
- 导航透明隐藏、滚动条及加载指示器有过局部 Native 工作量变化，但没有共同完成主慢帧与交互验收，当轮未恢复。
- 先判断采集是否覆盖问题，再解释帧时和内存。不根据不完整 heap 采样追加产品状态机、清缓存、提前析构或更大的采样缓冲。

## 下次从哪里继续

1. 找到专题，先读已验证结论、未验证范围和重开条件。
2. 查看当前实现与主要测试，确认历史重复工作或缺陷今天是否仍存在。
3. 只补能区分剩余假设的证据。已否决的路线只有在前提改变或出现新归因时才重开。
4. 新记录写清日期、输入、构建与环境、动作、观测、原因和限制。以可复用结论为正文，不把临时路径当作唯一答案。

具体命令、设备保护和证据分层继续使用[维护手册](../operator-runbook.md)与[测试标准](../testing-standard.md)。本手册保存的历史实验不代替当前版本的发布验收。
