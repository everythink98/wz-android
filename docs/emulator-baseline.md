这份记录描述“当前代码在当前登录态下是什么样”。以后优化代码时，新结果不要求和实时网站数字永久一致，但同一天、同条件、同登录态下不能无故少结果、丢字段、打不开详情或丢返回状态。

当前 `codex` 的 NodeSeek 结果来自已登录状态下的站内搜索；未登录时 NodeSeek 可能跳到 Google 搜索页，该路径作为兼容标准和自动化测试覆盖，不等同于本次模拟器结果。

### 搜索行为

| 功能 | 当前基线 |
| --- | --- |
| 最近搜索 | 点击 `codex` 只填入关键词，并显示“按键盘上的搜索键开始”；必须再次提交搜索 |
| 提交按钮 | 点击搜索按钮后可以正常搜索 |
| 搜索详情 | V2EX 首条结果可打开详情；详情显示来源、标题、作者、时间、回复数、浏览数和正文 |
| 搜索返回 | 从详情返回后仍停留在 `codex` 搜索页，结果和筛选状态保留 |
| NodeSeek 登录搜索 | 当前登录态下走 NodeSeek 站内搜索；首条详情可打开并返回 |
| NodeSeek 未登录兼容 | 未登录 / 仅验证时，允许读取受限 Google 搜索结果；结果仍显示为 NodeSeek 来源，首条详情可打开并返回；该路径由自动化测试固定，模拟器复测不能通过清数据制造未登录态 |
| 来源筛选 | 点底部 `搜索` 可回到搜索页顶部，再切换来源筛选 |
| 妖火筛选 | 筛选弹层显示 `全部版块`、`妖火茶馆`、`确认筛选` |
| linux.do 老帖 | `Google`、`Bing`、`DuckDuckGo` 是外部搜索入口；误触会打开 Chrome，返回 App 后搜索状态保留 |

注意：登录 / 验证网页不能用 Chrome 打开作为通过依据。必须从 App 的 `更多 -> 账号与验证` 入口打开，且页面仍在 `com.wz.reader` 内。

一次 ADB 键盘提交 `codex` 后 App 回到系统桌面；随后用 App 内提交按钮复测通过。该次记录视为自动输入路径异常，不作为搜索功能失败基线。以后如果真实键盘提交也复现，再单独作为 bug 处理。
