# 产品章程

## 产品定位

阅坛 Android 面向同时使用多个中文社区的 Android 用户，提供本地优先的发现、搜索、续读和必要互动体验。

四个来源共享阅读主干，但不追求互动能力完全对齐。登录、回复、投票、编辑、删除和上传等能力只在原站真实支持、当前账号真实允许且能够安全验证时提供。

## 核心用户旅程

1. 启动 App，浏览聚合或单站首页，打开主题并返回原列表状态。
2. 在全部或单一来源中搜索，打开结果并返回原关键词、筛选和结果状态。
3. 通过本机收藏、历史和关注用户继续阅读，不依赖云端账号体系。
4. 按需登录来源，在明确能力和权限下互动；失败时保留草稿并回滚本地乐观状态。

## 产品原则

- **已有能力默认保持**：产品地图中的现有可用能力是回归契约；修复、重构和回退不得静默降低功能，确需移除或改变时先取得用户同意。
- **本地优先**：Cookie、NodeImage API Key、代理和阅读资料留在设备；备份继续排除敏感字段。
- **阅读一致，互动按来源**：四站对齐发现、搜索、详情和续读主干，不伪造原站不存在的互动能力。
- **原站事实优先**：登录态、权限、字段和写操作目标必须来自 App 内原站数据，不靠作者名、文案或猜测补齐。
- **来源相互隔离**：单站失败不得污染其他来源；请求、缓存、错误和写操作不能串站。
- **状态连续**：详情、用户页、搜索和列表之间往返时保留必要的筛选、草稿、分页和滚动状态。
- **最小完整改动**：新能力必须能落到一条用户旅程，并带有与风险匹配的验证；不为假想扩展增加抽象或依赖。

## 非目标

- 不要求四站功能、字段或权限完全一致。
- 不替代原站所有管理、创作和账号设置能力。
- 不建设云端同步、跨设备账号体系或服务端内容镜像。
- 不以未登录页面、桌面浏览器或第三方客户端作为登录态能力依据。
- 不为短期文件大小或目录整齐进行无行为收益的大规模重构。

## 新功能准入

新功能进入开发前应同时满足：

1. 明确改善上述至少一条核心旅程，并说明目标用户可感知的结果。
2. 明确适用来源；来源能力不同可以不对齐，但不能伪造字段、权限或入口。
3. 不削弱本机数据、Cookie、代理 fail-closed、签名或备份敏感字段边界。
4. 定义失败、取消、登录失效和返回路径；写操作必须有防重复与状态回滚。
5. 有可执行的自动测试或只读真实行为验收；需要真实写操作时另行取得用户授权。

## 发布节奏

普通版本聚合几个小功能或 bug 后发布；崩溃、数据或隐私风险、核心来源不可用等阻断问题可以单独 hotfix。每个发布候选都要通过自动检查、正式构建检查和保留 App 数据的只读设备 smoke。
